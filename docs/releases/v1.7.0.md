A feature and correctness release: FILESTREAM test restores, three
restore bugs fixed, and operator docs. Live-verified on SQL Server 2022
Express (backup/restore byte-identical) and SQL Server 2019 Developer
(full→diff→log chain, 28,000 = 28,000 rows).

## New

- **FILESTREAM test restores.** `test-restore` and `restore-chain --as`
  place FILESTREAM files in their own folders under the server data dir
  (`<scratch>_fs`, `<scratch>_fs_1`, ...). Anything else that is not
  ROWS/LOG still refuses with "restore this database by hand".
- **DBA runbook** (`docs/DBA-GUIDE.md`), **LLM operator notes**
  (`AGENTS.md`), and a links block at the top of the README.

## Fixed

- **Duplicated PARTIAL** in restore SQL (`WITH PARTIAL,PARTIAL`).
- **Chain planner took copy-only diffs/logs** although copy-only backups
  are not part of a chain. Fulls already excluded them.
- **`--kill-connections` left the DB SINGLE_USER on success.** The
  MULTI_USER rollback now runs on success too (still a no-op for steps
  left RESTORING); a failed rollback is reported instead of swallowed.

## Known limits

- The SINGLE_USER success path was verified live; the old stranded
  behavior was confirmed by code read only.
- Live runs covered `local` storage and `zstd`. S3/Azure paths are
  covered by conformance runs, not by a SQL Server backup on this build.
- Still not run against a real AWS or Azure account.
