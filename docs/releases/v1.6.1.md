A patch release: **SQL Server 2025 on Linux now works**, and SqlSqueeze is now tested against a real SQL Server on every change, for free.

## Fixed

- **SQL Server 2025 on Linux could not take any backup** (v1.6.0 and earlier), failing with `libsqlvdi.so: undefined symbol: uuid_generate`. SQL Server 2025's VDI library needs libuuid and does not load it itself. The Linux shim (`native/linux`, rebuild it with `make`) now links libuuid. SQL Server 2022 is unaffected and still passes.

## New

- **Live CI.** A GitHub Actions workflow installs SQL Server natively on a free runner and runs 25 end-to-end checks (backup types, restore, `verify --sql`, `test-restore`, `unpack`, `restore-chain`, `backup-all`) on every push and pull request and weekly. Covered: SQL Server 2022 on Ubuntu 22.04, and 2025 on Ubuntu 22.04 and 24.04. It found the bug above on its first run. The checks are in `tools/live-test/linux-live.sh` if you want to run them against your own server.

## Known limits

- Not covered by live CI: SQL Server 2019 (its package needs `libldap-2.4`, which Ubuntu 22.04 does not ship) and Windows. Both are on the [roadmap](https://github.com/yantra3loka/sqlsqueeze/blob/master/ROADMAP.md).
- Everything in the v1.6.0 notes still applies, including that nothing has been tried against real S3 or Azure accounts.
- On Linux, rebuild the VDI shim on the SQL Server machine (`cd native/linux && make`, needs g++ and libuuid) and run as the `mssql` user.
